## 1. Scope

Everything v0.4 adds on top of v0.3:

- the Codex, Gemini and Copilot adapters: their invocation, flag checks, output parsing, config homes and context files (Part 1);
- `aipm auto`, entry-point plugins, OpenTelemetry tracing, the go and rust-cargo stacks and their dependency checks (Part 2);
- the release workflow, the CI and security workflows, Dependabot, the release build constraints, `install.sh`, and the whole system end to end (Part 3).

The attacker controls everything the v0.3 review lists (`idea.md`, every repository file including a cloned `.pm/` and `.git/`, every LLM response, agent output and diffs, test and scanner output, registry metadata), and also: the output of Codex, Gemini and Copilot (JSON events, final messages, exit codes, timing); anything an agent writes into its own config home during an attempt; `go.mod`, `go.work`, `Cargo.toml`, `.cargo/config*`, `build.rs`, toolchain files and Go-proxy and crates.io metadata; pull requests from forks (titles, branch names, commit messages, files); and a target repository's virtualenv, `.pth` files and PATH entries. The attacker does not control the user's terminal input, the user-level config, aipm's installed code and site-packages, or the user's `OTEL_*` variables.

## 2. Attack surface

### 2.1 Where T2 data enters (new in v0.4)

| Entry | Read by | Becomes |
|---|---|---|
| Codex JSONL events and Gemini's JSON object on stdout | `adapters/codex.py`, `adapters/gemini.py` (`parse_result`) | `AIPM-BLOCKED` questions, run artifacts; never a cost (both are charged their task budget) |
| Files an agent writes into its config home (`CODEX_HOME`, `GEMINI_CLI_HOME`, Copilot's) | the tool itself on its next run | rules, settings, hooks, extensions, skills the next attempt obeys |
| Context files a tool reads besides aipm's: `AGENTS.override.md`, `CLAUDE.local.md`, nested `AGENTS.md`/`GEMINI.md`, `.agents/skills/`, `.gemini/` | Codex, Claude Code, Gemini | instructions that override or extend aipm's managed rules |
| Tool configuration above the worktree or in the user's home: `.gemini/.env`, `go.work`, `.cargo/config*`, toolchain files, `~/.codex/`, `~/.gemini/`, `~/.copilot/`, `~/.cargo/config.toml`, Go's env file | Gemini, Go, Cargo, rustup, and the user's own later sessions | settings for every later task, inside aipm or not |
| `go.mod`, `go.sum`, `go.work`, `Cargo.toml`, `Cargo.lock` | `security/diff_checks.py`, the deps gate, `go mod download` in prepare | new dependencies, registry lookups, module fetches |
| Go-proxy and crates.io answers | `scanners/registry.py` | existence and age verdicts of the deps gate |
| The phase engine's state (`.pm/`) between `auto` steps | `app/auto.py` | which command `auto` runs next |
| Distributions in aipm's site-packages (`aipm.*` entry points) | `plugins/loader.py` | adapters, gates, scanners, providers and stacks |
| Pull requests from forks | `ci.yml`, `security.yml` | CI runs with a read-only token |

### 2.2 Where aipm executes, writes, prints or decides (new in v0.4)

- **Executes:** `codex exec`, `gemini` and (render-only) Copilot under the `agent` profile; `go`, `gotestsum`, `cargo`, `cargo nextest` as gates and prepare; plugin code at import; the OTLP exporter's network calls; the release workflow's build and publish jobs; `install.sh` and the uv installer it runs.
- **Writes:** each tool's config home (emptied and re-seeded per attempt); `GEMINI.md`, `.github/copilot-instructions.md` and `.agents/skills/` (managed blocks); the nextest config outside the worktree; release assets and attestations.
- **Prints:** each tool's blocked question; `auto`'s step log; `doctor`'s plugin list.
- **Decides:** the next `auto` step and when it stops; which plugins load; whether a Go module or crate is new, a typosquat or too young; which registries prepare may reach; what a release attests.

### 2.3 Compared with SECURITY.md §13.1

Two threats were missing and are added:

- **T-11:** tool configuration outside the worktree that a dispatched agent or gate reads (RT04-3, RT04-6, RT04-11): a `.gemini/.env`, `go.work` or `.cargo/config.toml` beside the worktrees, or the user's own `~/.codex/AGENTS.override.md`, `~/.cargo/config.toml` or Go env file, planted for every later task and every later session.
- **E-7:** the release or install path delivers code other than the attested build (RT04-16 to RT04-19).

D-2 gained deeply nested JSON (RT04-1, RT04-10); T-5 gained context files that override aipm's (RT04-2); E-5 gained plugins that shadow a shipped stack (RT04-15).

## 3. Attacks tried

Result: **Bypassed** means the attack worked before this pass and is now fixed (section 4). **Held** means the existing controls stopped it; each held row from the new tests has a `test_pin_*` test. **Not run**, **By design** and **Residual** are explained in the row.

### 3.1 Every invariant against every dispatchable adapter

`tests/e2e/test_hostile_world.py` runs once per dispatchable tool. Copilot is render-only (ADR-0025): `build`/`run --tool copilot` exits 8 (`test_multi_tool_scenarios.py`, Part 1 item 7), so it has no dispatch to attack.

| I-2 agents in their worktree; aipm in its paths | held (profile as written) | held (profile as written) | held (profile as written) | the main checkout is byte-identical after the build; every profile is read when its process starts: each process that runs agent-written code (agent, prepare, command gates) is denied every top-level entry but `.git`, and each built-in scanner the credential paths (§9.1); the user's agent config write is severe |

### 6.3 Decisions for the owner

The owner's choices, and what was done, are in §6.4.

**v0.1 O-1 (medium): a user config in another directory.** A repository `.env` loaded by pipenv can set `AIPM_CONFIG` (or `HOME`) to a file in that repository; after `cd ~/other-repo` in the same shell, aipm reads it as the user config, with power over `llm.base_url`.
- (a) Derive the default config and state directories from the account (`pwd.getpwuid`), not `HOME`/`XDG_*`; only an explicit `AIPM_CONFIG` moves them. Closes the `HOME` path; `AIPM_CONFIG` stays.
- (b) Refuse a user config or trust store inside any git work tree. Closes both, but breaks users whose home directory is a work tree (dotfiles).
- (c) Warn on every run when `AIPM_CONFIG` is set. Cheap; relies on the user reading it.
- *Recommended: (a) + (c).*

**v0.1 O-2 (low): a missing `AIPM_CONFIG` file** silently drops the whole user config. (a) Exit 6 when `AIPM_CONFIG` names a missing file (changes behaviour that `tests/unit/test_config.py` relies on, so those tests would need your approval to change); (b) warn; (c) accept. *Recommended: (a).*

**v0.1 O-3 (low): TOCTOU for the user config** (a link swapped between `is_within` and `open`). Needs a concurrent writer in the repository. (a) Accept as residual; (b) open once with `O_NOFOLLOW` and check the descriptor. *Recommended: (a), unchanged since v0.1.*

**v0.1 O-4 (info): `init` reads the user config with `load_config(None)`.** It reads only a tighten-only size limit, and the trust step that follows refuses. (a) Accept; (b) pass the root. *Recommended: (b), a one-line change.*

**v0.2 O-1 (low): `--ignore-pnpmfile`** in the `node-pnpm` prepare argv. A `.pnpmfile.cjs` the repository already had runs in prepare. (a) Add the flag (changes the argv `test_v02_templates_pass_the_policy` pins, and breaks repositories that need their pnpmfile); (b) accept under R-13. *Recommended: (a); prepare now runs after a sandboxed agent in every build.*

**v0.2 O-2 (medium): a private package cache for prepare** (R-13). (a) A per-attempt cache directory for uv, npm, pnpm, Go modules and Cargo, passed through the environment (slower first runs, more disk); (b) a per-run cache shared by the run's tasks; (c) accept. *Recommended: (b); it also answers Part 2's question whether Go and Cargo work under the real `srt` (observation E in section 7).*

**N-1 (medium): `go mod download` exfiltrates through module paths** (R-20).
