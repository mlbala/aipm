## 1. Scope

Everything v0.3 adds on top of v0.2:

- `aipm build`, `aipm run` and `aipm merge`;
- the Claude Code adapter's invocation (`build_invocation`) and its parsing of the agent's output (`parse_result`);
- the dispatcher and the agent's sandbox profile;
- task worktrees, the integration branch, rebase and `update-ref`;
- the run journal and resume;
- the scheduler, budgets and the token counter;
- stopping every process group at once;
- the `done` state that `build` and `merge` act on.

Where v0.3 changed the v0.2 surface, it was attacked again: the post-change checks on a worktree, and the gates and prepare step in a build.

The attacker controls any combination of: `idea.md`; every file in the target repository (including a cloned `.pm/`, and a `.git/` copied with it, which can carry `aipm/*` branches and `.pm/runs/` journals); every LLM response; the agent's output, diffs and every file its gate code writes; test and scanner output; and registry metadata. The attacker does not control the user's terminal input, the user-level config (including the global git config) or aipm's installed code.

`srt`, gitleaks, semgrep, osv-scanner and trivy were not installed on the test machine. The sandbox was attacked through the profile aipm writes: the stub `srt` in `tests/fakes/bin/` now copies every settings file it receives, and the build tests read the profile each process got. Real enforcement was not exercised (recommendation 3). Claude Code 2.1.314 is installed. Its behaviour around `CLAUDE_CONFIG_DIR` was confirmed by reading strings in the installed binary; it was not run beyond `--help`. git was tested in both versions on the machine: 2.55.0 (Homebrew) and 2.54.0 (Apple Git-157, `/usr/bin/git`).

## 2. Attack surface

### 2.1 Where T2 data enters (new in v0.3)

| Entry | Read by | Becomes |
|---|---|---|
| The agent's stdout: stream-json events, the `result` event (`total_cost_usd`, `session_id`, `is_error`, `subtype`, final text) | `adapters/claude_code.py` (`parse_result`) | the attempt's cost, the session `--resume` names, `AIPM-BLOCKED` questions, run artifacts |
| The agent's config home (`CLAUDE_CONFIG_DIR`): transcripts, `.claude.json`, `shell-snapshots/`, `session-env/`, `daemon.json` | Claude Code itself on the next `--resume` | what the next attempt runs before every Bash command, and its grants |
| The worktree after the agent and its gate code ran, including repositories created inside it | `execution/git.py`, `security/diff_checks.py` | the change set, the checks, the commit, the rebase |
| Processes the agent leaves behind (a child in its own session) | the worktree, the config home | anything aipm reads or commits afterwards |
| A copied `.git`: `aipm/integration`, `aipm/task/*` branches, `.git/worktrees/*` | `execution/worktree.py` | the base every task builds on, what `merge` fast-forwards |
| `.pm/runs/<run>/journal.jsonl` and `cost.json` from a copied repository | `execution/journal.py`, `app/status.py` | what a resumed build trusts, the spend shown |
| `tasks.yaml` from a cloned repository: statuses, `done` records, ownership globs | the scheduler, `status`, `build` | which tasks run together, which never run |

### 2.2 Where aipm executes, writes, prints or decides (new in v0.3)

- **Executes:**
  - outside any sandbox: `git worktree add/remove`, `rebase` in a fresh worktree, `update-ref` (compare and swap), `commit`, `merge --ff-only`;
  - Claude Code under the `agent` profile, then prepare and the gates under theirs.
- **Writes:**
  - the task worktrees, the rebase worktree and the agent config homes, all in the user cache directory;
  - the integration tips and the new `done` record, both in the user state directory;
  - the journal, prompts, agent output, reports and `cost.json` in `.pm/runs/`;
  - `tasks.yaml` and the worksheet.
- **Prints:** live progress, the end-of-build summary, blocked questions, the `merge` log.
- **Decides:**
  - which tasks run together;
  - each attempt's cost and whether the next one fits;
  - severe or minor, and retry or block;
  - commit, rebase or conflict;
  - resume or start fresh;
  - `done`.

### 2.3 Compared with SECURITY.md §13.1

Two threats were missing and are added:

- **T-10:** a dispatched agent reads secrets outside its worktree (RT03-1, RT03-2, RT03-3). SG-4 promised "its own worktree only", but the profile denied reads of only the credential directories, the main `.pm/` and the worktrees that already existed.
- **D-4:** spend is counted short (RT03-7, RT03-8). D-1 covered runaway cost, not a run budget that counts less than was spent.

T-6 (an agent persists through its global config) gained a new path: Claude Code's background service and `~/.claude/daemon.json` (RT03-5). E-2 gained one too: state in the agent's own config home that Claude Code runs before every Bash command (RT03-4).

## 3. Attacks tried

Result: **Bypassed** means the attack worked before this pass and is now fixed (section 4). **Held** means the existing controls stopped it; every held row from the new tests has a `test_pin_*` test. **By design**, **Residual** and **Not reachable** are explained in the row.

### I-1: no process starts with an argv outside the trusted menu or fixed fragments

| 4 | A `claude` or `node` planted in an active `.venv/bin` in the repository or a worktree | Held (step 07 tests) |
| 5 | A copied `aipm/task/T-002` at a planted commit | Held: the worktree is made from the integration branch, and the planted commit never reaches it (pin) |

### I-4: no task becomes `done` without every required gate passing on its diff

| # | Technique | Result |
|---|---|---|

## 5. Fuzzing

`tests/property/test_redteam_v03_props.py` adds eight properties. `uv run pytest tests/property --hypothesis-profile=ci-long` runs each at least 2,000 times; the v0.1, v0.2 and step 07 properties still pass.

| Target | Property |
|---|---|
| Scheduler (oracle) | Two globs `globs_may_overlap` calls disjoint match no common file, with paths compared as macOS compares names |
| Scheduler (respelling) | A glob and the same glob in another case or Unicode normalization always conflict |
| `blocked_question` | Any text gives `None`, or one line of at most 300 characters with no control, format, separator or invisible character |
| `parse_result` | Any stdout gives a bounded result; the cost is never lower than any `result` event's total |
| `Spend` | Over any sequence of scheduling, starting, settling and releasing, a hold is granted only when the spend plus every hold fits in `run_usd` |
| `replay` | Any journal gives a finite, non-negative spend, and an agent that never finished is charged |
| Agent profile | For any main checkout (including one that is the home directory), every top-level entry except `.git` is denied unless it holds a path the agent needs, and no writable path lies under a denied one |
| `--allowedTools` | A word outside the rule alphabet is refused; every rule allows exactly its words |

The `ci-long` runs found RT03-10. The default 100 examples did not, which is recommendation 6 of v0.1 again.

## 6. Residual risks and open decisions

**O-3, settled.** Run on this machine, with a hook `probe` for `post-commit` defined in a scratch global config. `test_o3_what_each_git_here_does_with_a_global_config_hook` repeats this on every git a machine has: the one on `PATH`, and `/usr/bin/git`.

| git | No switch | `hook.post-commit.enabled=false` (aipm's) | `hook.probe.enabled=false` |
|---|---|---|---|
| 2.55.0 (Homebrew) | runs | stopped | stopped |
| 2.54.0 (Apple Git-157, `/usr/bin/git`) | runs | **runs** | stopped |

Requiring git 2.55 would have refused macOS's own git. The owner chose to refuse git 2.54 only while a config it reads in that repository names a hook (exit 8, naming the hooks, conditional includes included). `aipm doctor` says so.

SECURITY.md §15 changes:

- **R-14** now covers the agent too: a child in its own session outlives its attempt on macOS, under the same sandbox. A task's worktree path is reused by its next attempt and its next build. Such a child is detected (`changed_during_gates`, `commit_mismatch`, tested), not prevented.
- **R-15 (new):** a run can pass `budget.run_usd` by up to one model turn for each running attempt, because Claude Code checks `--max-budget-usd` between turns.
- **R-16 (new):** a dispatched agent can still read the main checkout's `.git`, every branch's objects and the repository config, where a remote URL may hold a token. Without `srt` it can read and write anything the user can.
- **R-17 (new):** a done task that a cloned `tasks.yaml` claims still unlocks the tasks after it. The owner chose to flag such tasks rather than block.

Still open for the owner (the definition of done of build prompt 09):

- **v0.2 O-1 (low):** `--ignore-pnpmfile` in the `node-pnpm` prepare argv. Not chosen this pass.
- **v0.2 O-2 (medium):** a private package cache for prepare (R-13). Not chosen this pass.
- **v0.1 O-1 to O-4:** unchanged.

## 7. Recommendations for v0.4

1. **Give each task start a fresh worktree path** (a random suffix, recorded in the journal), so a child an earlier attempt left behind on macOS (R-14) no longer holds write access to the tree that is built next.
2. **Adopt the same read rules for every adapter.** Codex, Copilot and Gemini get the ADR-0024 profile; for a tool whose config home cannot be relocated, deny its token files by name.
3. **Run the real `srt` in CI for the red-team suite** (v0.2 recommendation 6, still open). Without it, the profile is tested as written, not as enforced. Also gitleaks, semgrep and osv-scanner.
4. **Watch the main checkout when there is no sandbox**: record a security event when its status changes during an attempt, as a warning, since the user may be editing.
5. **Decide v0.2 O-1 and O-2.** The prepare step now runs after a sandboxed agent in every build.
6. **Run `ci-long` nightly** (v0.1 recommendation 6, open for the third time; RT03-10 is the second finding only it found).
7. **Attack the v0.4 surfaces first:** the Codex, Copilot and Gemini adapters (flags, output parsing, their config homes), `auto`, plugins and the release pipeline.
